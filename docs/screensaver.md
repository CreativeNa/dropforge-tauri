# Режим заставки для монитора (Screensaver)

Проектная записка: режим заставки/удержания экрана для DropForge.
Статус: **идея, код не меняем — только подготовка**. Ниже — что уже есть в коде под это и куда встраивать.

## Что просили

«Screensaver-режим для монитора» — чтобы во время фарма экран/система не уходили в сон, и/или чтобы приложение показывало заставку со статусом фарма, пока пользователь отошёл.

Под это подходят две разные функции, их лучше делать вместе, в одной секции «Монитор»:

1. **Не гасить экран** — во время фарма монитор и система не засыпают.
2. **Заставка** — полноэкранный экран со временем и статусом фарма; любой ввод мыши/клавиатуры возвращает к обычному окну.

## Что уже готово в коде (точки встраивания)

| Что | Где | Как используется |
|---|---|---|
| Трей и меню | `rust/tauri-app/src/main.rs`, блок `.setup(...)`, строки ~2040: `MenuItem::with_id(app, "show", …)`, `Menu::with_items`, `on_menu_event` | сюда добавляем пункт «Заставка» |
| Настройки | `load_settings()` (там же, ~1550) и `settings_save` | сюда добавляем ключи заставки |
| Снимок состояния | `snapshot_from_profile()` | заставка берёт из него статус фарма, канал, минуты |
| Опрос состояния в UI | `src/ui/tauri-shim.js` (polling `app_snapshot` каждые 5 с) | заставка сможет жить на том же мосте |
| Статус фарма | `STATUS`/`status_value()`, `MINER`, `pubsub-svc` | источник данных для заставки |
| Windows API | `windows-sys` уже подключён (DPAPI, мьютекс) | добавляем фичу `Win32_System_Power` |

## Реализация

### 1. Не гасить экран

Win32 `SetThreadExecutionState`:

- включить: `ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED` (0x80000000 | 0x00000001 | 0x00000002);
- выключить: `ES_CONTINUOUS` (0x80000000).

Правила:

- включать только когда фарм реально идёт (`STATUS.running == true`);
- снимать при остановке фарма, выходе из приложения, сворачивании в трей при выключенной опции;
- отдельный режим «только системный сон» (`ES_SYSTEM_REQUIRED` без `ES_DISPLAY_REQUIRED`) — экран гаснет, но компьютер не засыпает (полезно для ночного фарма).

Проверка: `powercfg /requests` должен показывать поток DropForge в разделе DISPLAY.

Альтернатива без WinAPI — `powercfg /requestsoverride`, но это глобальная настройка системы, её лучше не трогать.

### 2. Заставка (полноэкранное окно)

Отдельное окно Tauri:

- `fullscreen: true`, `decorations: false`, `alwaysOnTop: true`, `skipTaskbar: true`, `label: "screensaver"`;
- контент — отдельная страница `src/ui/screensaver.html` (+ `screensaver.js`), данные через тот же `tauri-shim.js`;
- показывает: часы, дату, статус фарма (канал, игра, текущий дроп, минуты, прогресс), счётчики «накоплено», иконку сервиса;
- фон затемнён, крупный шрифт, без интерактива кроме выхода.

Выход:

- по клику/любой клавише внутри окна (события `click`, `keydown`);
- по отсутствию ввода N секунд → вход, по появлению ввода → выход: `GetLastInputInfo` (WinAPI, та же фича `Win32_System_Power`/`Win32_UI_Input_KeyboardAndMouse`) опросом раз в секунду;
- закрытие окна = возврат к главному окну.

Мультимонитор:

- вариант «на всех экранах» — создавать окно на каждом мониторе (Tauri `available_monitors`, отдельные label `screensaver-1…N`);
- вариант «только на основном» — по умолчанию.

### 3. Настройки (новые ключи `settings.json`)

```json
{
  "keepAwakeMode": "off",
  "screensaverMode": "off",
  "screensaverIdleMinutes": 5,
  "screensaverShowStats": true,
  "screensaverAllDisplays": false,
  "screensaverOnBattery": false
}
```

- `keepAwakeMode`: `off` | `display` | `system`.
- `screensaverMode`: `off` | `overlay` | `overlay+dim`.
- `screensaverOnBattery`: на ноутбуке от батареи не держать экран (по умолчанию `false`).

### 4. Меню (куда именно встраивать)

В трей-меню (файл `main.rs`, блок `.setup`):

```
Открыть DropForge
─────────────
Не гасить экран: вкл/выкл        ← подпись меняется по состоянию
Заставка: включить / выключить   ← подпись меняется по состоянию
─────────────
Выход
```

Технически: два `MenuItem::with_id(app, "keepawake-toggle", …)`, `MenuItem::with_id(app, "screensaver-toggle", …)` и вставка в `Menu::with_items(app, &[&show, &keepawake, &screensaver, &quit])`. Подписи обновлять через `MenuItem::set_text(...)`; чтобы иметь к ним доступ из команд, хранить их в `MinerState` (или отдельном `TrayState`).

В интерфейсе:

- в сайдбаре новый пункт **«Заставка»** рядом с «Настройки» — открывает экран предпросмотра заставки и её настройки;
- в «Настройках» секция **«Монитор»**: режим удержания экрана, заставка, таймаут, показывать ли статистику, все мониторы, поведение на батарее;
- кнопка «Запустить заставку сейчас» — для проверки.

### 5. Команды Tauri (новые)

- `keepawake_set(mode)` — включить/выключить удержание;
- `screensaver_open()` / `screensaver_close()` — открыть/закрыть окно заставки;
- `screensaver_status()` — активно ли, какой режим (для подписей меню и UI).

## Крайние случаи

1. **Игровой fullscreen** — окно заставки не должно лезть поверх эксклюзивного полноэкранного режима; вариант: не включать `alwaysOnTop`, если активно приложение в полном экране (проверка через `GetForegroundWindow` и стили окна).
2. **Мультимонитор** — окно на каждом экране; при отключении монитора — пересоздать.
3. **Смена питания** — при переходе на батарею выключать удержание (если опция выключена).
4. **Спящий режим Windows/Lock** — заставка не должна мешать блокировке экрана (Win+L); при блокировке окно можно не трогать.
5. **Выход из приложения** — обязательно снять `ES_CONTINUOUS`, иначе Windows останется «разбуженной» до перезагрузки (на практике сбрасывается при завершении потока, но лучше явно).
6. **Несколько экземпляров приложения** — уже защищено мьютексом.

## План работ

1. Настройки и команды `keepawake_set` / `screensaver_*` (1 итерация).
2. Удержание экрана (`SetThreadExecutionState`, проверка `powercfg /requests`) (1 итерация).
3. Окно заставки + страница `screensaver.html` со статусом фарма (2 итерации).
4. Выход по вводу (`GetLastInputInfo`) и мультимонитор (1–2 итерации).
5. Меню трея с динамическими подписями (1 итерация).
6. Секция «Монитор» в настройках + пункт «Заставка» в сайдбаре (1–2 итерации).
7. Проверка на живом фарме: экран не гаснет, заставка показывает статус, любой ввод возвращает окно (2 итерации).

Итого: 8–11 итераций сборки.

## Риски

- Заставка может мешать работе пользователя, если включена без таймаута — поэтому по умолчанию `off` и выход по любому вводу.
- Удержание экрана расходует энергию и может конфликтовать с корпоративными политиками питания.
- Статичная картинка на OLED-мониторах — риск выгорания; в заставке предусмотреть лёгкое смещение элементов и приглушённые тона.
- На Twitch это никак не влияет (это только локальное поведение машины).

## Открытые вопросы

1. Нужно оба режима (не гасить экран + заставка) или только «не гасить»?
2. Заставка на всех мониторах или только на основном?
3. Показывать ли на заставке статистику фарма (канал/дроп/минуты) или только часы?
4. Держать экран всегда при фарме или только при бездействии пользователя?
